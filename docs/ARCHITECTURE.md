# Архитектура Booktracker: MVC + слои

Средняя сложность №10: описание архитектуры MVC для приложения.

## Зачем разделять приложение

Booktracker — консольная программа учёта книг. Если писать её одним файлом, в одной функции смешаются разбор аргументов, проверки правил («оценивать можно только прочитанные книги»), запись JSON-файла, HTTP-запрос и форматирование вывода. Такой код трудно тестировать: чтобы проверить правило про оценку, пришлось бы запускать CLI, создавать файл и ходить в интернет.

Поэтому приложение построено по шаблону **MVC** (Model — View — Controller), а модель дополнительно разделена на **слой сервисов** и **слой данных** (Repository).

## Компоненты

```text
                  ┌──────────────────────────────┐
  командная       │  Controller   cli.py         │  разбирает аргументы (argparse),
  строка  ──────► │                              │  вызывает сервис, передаёт
                  └───────┬──────────────┬───────┘  результат во View
                          │              │
                          ▼              ▼
  ┌───────────────────────────────┐  ┌──────────────────────────┐
  │ Model                         │  │ View   views.py          │
  │                               │  │                          │
  │  services.py   BookService    │  │ book_line, book_list,    │
  │    правила предметной области │  │ stats — только           │
  │              │                │  │ форматирование текста    │
  │              ▼                │  └──────────────────────────┘
  │  repositories.py              │
  │    BookRepository (ABC)       │
  │     ├ InMemoryBookRepository  │
  │     └ JsonBookRepository ─────┼──► ~/.booktracker.json
  │                               │
  │  openlibrary.py               │
  │    OpenLibraryClient ─────────┼──► https://openlibrary.org (requests)
  │                               │
  │  models.py   Book (dataclass) │
  └───────────────────────────────┘
```

| Часть MVC | Модули | Отвечает за | Не знает о |
|---|---|---|---|
| **Model** | `models.py`, `services.py`, `repositories.py`, `openlibrary.py` | данные, правила, хранение, внешний API | командной строке и формате вывода |
| **View** | `views.py` | превращение объектов `Book` и статистики в текст | где лежат данные, какие есть правила |
| **Controller** | `cli.py` | разбор команды, вызов нужного метода сервиса, выбор представления, код возврата | как устроено хранение и правила |

## Модель изнутри: слой сервисов и слой данных

**Слой сервисов** (`BookService`) содержит все правила:

- ISBN нормализуется и проверяется, повторно добавить ту же книгу нельзя (и в API при этом не ходим);
- прочитанную книгу нельзя снова «начать»;
- оценка ставится от 1 до 5 и только прочитанной книге;
- статистика: прочитано книг и страниц, средняя оценка.

**Слой данных** — шаблон **Repository**. Сервис работает с абстрактным `BookRepository` (методы `add`, `get`, `list`, `update`, `delete`, `find_by_isbn`) и не знает, куда пишутся данные. Реализаций две:

- `JsonBookRepository` — файл JSON с атомарной записью через временный файл;
- `InMemoryBookRepository` — словарь в памяти для тестов.

Чтобы перейти, например, на SQLite, достаточно написать третью реализацию. Сервисы, CLI и представление при этом не меняются.

**Внешний сервис** `OpenLibraryClient` тоже передаётся в сервис снаружи (внедрение зависимостей), поэтому в тестах его заменяет `FakeInfoClient` без сети.

## Путь одной команды

`booktracker rate 1 5`:

1. **Controller** (`cli.main`) — `argparse` проверяет, что `rating` входит в 1..5, и создаёт `BookService(JsonBookRepository(db), OpenLibraryClient())`.
2. **Controller** (`cli.run`) вызывает `service.rate(1, 5)`.
3. **Model / сервис** получает книгу через репозиторий, проверяет, что она прочитана, ставит оценку и сохраняет через `repository.update`.
4. **Model / данные** — `JsonBookRepository` перезаписывает файл.
5. **View** — `views.book_line(book)` формирует строку `#1 … [прочитана] ★★★★★`.
6. **Controller** печатает её и возвращает код 0. При нарушении правила `ServiceError` превращается в сообщение в stderr и код 1.

## Как это проверяется тестами

| Слой | Тесты | Что подменено |
|---|---|---|
| Данные | `test_repositories.py` — одни и те же тесты для обеих реализаций (параметризованная фикстура) | ничего, JSON пишется во временную папку |
| Сервисы | `test_services.py` | репозиторий в памяти, фейковый клиент API |
| Внешний API | `test_openlibrary.py` | `requests.Session` — объект `Mock` |
| Controller + View | `test_cli.py` — вызов `cli.main([...])` и проверка stdout/stderr | фейковый клиент API |
